# 王子 Comment Reader 🌙

note「nero_notelover」専用の未返信コメント管理サイトです。

## できること

- 王子の記事一覧を取得
- コメントがある記事だけコメントスレッドを確認
- 王子の最後の返信より後にある他ユーザーのコメントを未返信として抽出
- 未返信コメントを新しい順に一覧表示
- ChatGPTへ相談用プロンプトをワンタップでコピー
- noteの記事をすぐ開ける
- 条件に合うスキ候補を最大30人まとめて表示し、記事を開いて手動でスキできる
- GitHub Actionsで定期同期
- GitHub Pagesで表示

既存の静的コメント一覧はAI API・有料DBを使いません。MCP/会員版はCloudflareを使用します。

## 手動で回るスキ候補

既存画面の「スキ候補」タブで、最大30人分の名前・人数・最新記事をまとめて確認できます。公開済みの候補は画面を開いた時と表示中に自動で読み直します。

最初に「王子のGitHubで接続」で本人確認すると、この画面の「候補を30人探す」で新しい候補を取得できます。記事を読んでから、各行の「♡ スキを届ける」を押した時だけ、その1件を送信します。GitHubの実行画面へ移動する必要はありません。

スキ済みをサーバーで確認できた記事は、候補一覧・人数・URLコピー対象から外れます。ブラウザ内にも確認結果を記録するため、再読み込み後も再表示しません。「確認済み」は別の手動作業記録です。

未接続でスキや検索を押すと、その場で本人確認へ進みます。認証完了後に、対象のスキボタンをもう一度押してください。短期のReader専用認証は同じタブのsessionStorageに保存し、再読み込み後に復元します。note CookieやGitHubトークンはブラウザへ渡しません。

送信結果が不明な記事は一覧に残し、再送せず読み取りで結果を確認します。noteが明確に拒否した送信や、送信前に認証不足で止まった場合だけ、状態を再確認して次の手押しで再試行できます。画面表示、候補検索、本人確認によってスキを自動送信する処理はありません。

候補は次の条件をすべて満たす人です。

- 王子（`nero_notelover`）自身を除く
- 王子がフォローしておらず、相手からもフォローされていない
- フォロー数がフォロワー数の1.15倍以上、かつ10人以上多い
- 直近30日以内の記事があり、取得できた最近の記事一覧に王子がスキ済みの記事がない
- フォロー関係・人数・スキ状態を確認できる

1人につき取得範囲内の最新記事を1件選び、集まった候補を人数差の大きい順、同点なら記事の新しい順に並べます。本文のテーマによる選別はありません。探索上限・通信制限・条件に合う人数によって30人に届かない場合は、実際の人数と途中終了の理由を表示します。記事一覧1ページ目で取得できた直近30日分を判定するため、過去全記事のスキ履歴を確認した結果ではありません。

定期収集の抽出ロジックと再利用ワークフローはこのリポジトリの `scripts/collect-like-candidates.mjs` と `.github/workflows/like-candidates.yml` にあります。`Prince_like_giver` のGitHub Actionsから呼び出します。

登録済みの `NOTE_SESSION_COOKIE` は、GitHub Actionsの署名付きOIDCで本人のmainワークフローを確認した場合にだけ、既存のCloudflareサーバーへ同期します。サーバーでもnoteの本人アカウントを確認してから暗号化保存します。Cookieを画面へ渡したり、新しいSecretを手作業でコピーしたりする必要はありません。GitHubの本人確認は既存の権限のままで、リポジトリ操作権限の追加も求めません。

取得結果は呼び出し元リポジトリの `manual-candidates` ブランチに `data/like-candidates.json` として保存し、Comment Readerから読み込みます。候補の公開プロフィール・記事URL・選定に使う人数などは公開データとなります。認証CookieとGitHubトークンは保存・表示しません。認証拒否やアクセス制限があった実行では前回の公開結果を保持します。

- 「候補を30人探す」：画面内で新しく検索し、進捗と結果を表示します。
- 「最新候補を表示」：保存済みの最新結果を読み込みます。
- 「♡ スキを届ける」：本人が押した記事に1件だけ送信します。
- 「接続できないとき」内のGitHubリンク：サーバーの接続に問題がある時に、従来の定期収集を手動で実行する補助導線です。

候補の収集は `Prince_like_giver` の定期実行でも更新します。GitHub Actionsの混雑やnote側の制限により、更新が遅れることがあります。

開発用の `npm run test:candidates` は通信しないテストのみを実行し、実際の記事へスキを送りません。

## 2026年10月：高速差分同期

- 取得操作ごとに記事一覧を**1回**取得し、前回からコメント件数が変わった記事を優先走査
- 未対応コメントが残るスレッドは件数が変わらなくても確認（スキ・返信による対応完了を検出）
- 取得エラーのある記事は判定保留にして次回再試行
- 結果と記事ごとの状態を Cloudflare Durable Objects に保存（次回の差分判定に利用）
- 週単位の分散した再検証で件数だけでは検出できない変化も補助チェック
- 過去の `/comments/live` API は互換性のため残しています

**コードをGitHubに反映しただけでは、Cloudflare Workerは更新されません。**
高速更新を有効にするには、従来のMCP Workerを再デプロイしてください。

```sh
cd mcp
npx wrangler deploy
```

反映まではWeb画面は従来APIにフォールバックします。

## 城下町向け会員版（別アプリ）

note IDを入力するだけで使える（メール認証なしの）会員版を `members/` に用意しました。
ログアウトはブラウザの利用情報を解除する操作です。
**設置手順と会員メールの管理方法は [members/README.md](members/README.md) を参照**してください。

既存のGitHub Pagesは公開サイトであり、ログイン画面だけで会員限定にはできません。
会員向けページは別のCloudflare Workerで運用します。
メンバーシップ限定記事でURLを配る方式のため、リンクを知った非会員を技術的に排除することはできません。
